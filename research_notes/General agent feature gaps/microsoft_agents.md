# Microsoft general-purpose agents (as of 2026-09-29)

Naming: Windows Autopilot is not an AI agent. Microsoft Learn describes it as a collection of technologies used to set up and pre-configure new Windows PCs or HoloLens 2 devices, join them to Microsoft Entra ID or hybrid Active Directory, auto-enroll them in MDM such as Intune, and reset or repurpose devices. It is a device-lifecycle product, not a general assistant. A separate 2025–2026 product line is branded Autopilot and is an AI agent: on 2 June 2026 Microsoft introduced a category called Autopilots and a first agent, Microsoft Scout; the 25 September 2026 official Copilot announcement says Autopilot was previously called Scout and that the Scout page now states “Microsoft Scout is now Autopilot.” Microsoft Foundry separately documents “autopilot agents” (public preview, June 2026) as a category of autonomous agents with their own user accounts. Those are the products a person means by a general agent named Autopilot. Sources: [Overview of Windows Autopilot](https://learn.microsoft.com/en-us/autopilot/overview); [Introducing Microsoft Scout](https://www.microsoft.com/en-us/microsoft-365/blog/2026/06/02/introducing-microsoft-scout-your-always-on-personal-agent/); [Introducing the new Copilot with Home, Code and Autopilot](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/); [Foundry enterprise agent distribution](https://devblogs.microsoft.com/foundry/from-building-agents-to-working-with-them-enterprise-agent-distribution-in-microsoft-foundry/).

Products inventoried below, all from pages opened on 2026-09-29: Microsoft 365 Copilot chat and declarative agents; first-party Researcher (and Analyst only where the Researcher FAQ names it); Copilot Studio autonomous agents, event triggers, and agent flows; Copilot Studio computer use; Windows Copilot Actions; Copilot Autopilot/Scout; Foundry autopilot agents. Visual Studio “agent mode” and the Windows Settings on-device settings helper were not treated as general-use agents.

## What can these agents do without a user sitting in a coding session?

### Takeaway
Several Microsoft agents already run outside a coding session: chat and delegated work in Microsoft 365 Copilot, scheduled or event-driven Copilot Studio agents, GUI automation on a Windows machine or Cloud PC, local desktop actions in a Windows agent workspace, and always-on tenant agents (Autopilot/Scout and Foundry autopilot agents) that keep working when the person is away. Most of the always-on products were still preview or private preview as of the 25 September 2026 announcement.

### Cited Findings
- Microsoft 365 Copilot agents “range from simple prompt-and-response agents to more advanced, fully autonomous agents” and “automate and execute business or education processes, working alongside or on behalf of a person, team, or organization.” Users build simple agents in Copilot Agent Builder inside chat; “more advanced scenarios” go to Copilot Studio. — [Agents for Microsoft Copilot Chat](https://learn.microsoft.com/en-us/copilot/agents)
- Researcher is a first-party agent inside Microsoft Copilot for complex, multi-step research. It draws on the web and work content the user can access, including files, emails, meetings, and chats, and returns a source-cited report with sections and visuals. It may ask clarifying questions. It is under Agents in Chat and is part of the default experience for Microsoft Copilot licensed users. It is also on iOS and Android. It uses Microsoft Graph, connectors, and the Bing index, and includes archived mail as backfill when the primary inbox lacks data. A response is typically under five minutes for simple queries and 10 to 45 minutes for highly complex ones. It does not run as an unprompted background worker: the user opens Researcher and asks a question. — [What is Researcher Agent](https://learn.microsoft.com/en-us/microsoft-365/copilot/researcher-agent); [Researcher FAQ](https://learn.microsoft.com/en-us/microsoft-365/copilot/faq-researcher)
- The same Researcher FAQ says the Analyst agent “is better suited for Microsoft Excel related tasks,” and that admins can block Researcher and Analyst. This inventory did not open a dedicated Analyst product page, so Analyst’s tool loop is not described here beyond that FAQ. — [Researcher FAQ](https://learn.microsoft.com/en-us/microsoft-365/copilot/faq-researcher)
- The 25 September 2026 Copilot app splits work into Home, Code, and Autopilot. Home combines Chat and Cowork. Chat is “instant and conversational” for questions, lookups, and drafts. Cowork is “work you delegate”: the user defines the task and it “runs end-to-end” and returns a completed result (examples given: an RFP response, a launch kit, a customer briefing, a financial close package). Office in Copilot creates or updates a real Word, Excel, or PowerPoint file from Home. “Coming soon,” Copilot will route a request to Chat, Cowork, or Code without the user picking a mode. Code is a natural-language app/dashboard/automation builder in a sandbox and is the coding surface, not the general agent. — [New Copilot, 25 Sep 2026](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)
- Cowork, Code, and Autopilot, plus “new long-running agentic capabilities” and frontier models “Astra and Fable,” run on usage-based billing, not the fixed user-subscription license that covers everyday Chat and Copilot in Word, Excel, PowerPoint, Outlook, and Teams. Home and Code start rolling out in the Frontier program “in the coming weeks”; Autopilot “is expanding to private preview at the end of the month” (September 2026). — [New Copilot, 25 Sep 2026](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)
- Autopilot, previously Scout, is described as a “persistent, proactive and personal agent” and “digital teammate.” The user gives it a name, a role, and a goal. It watches channels, follows up on threads, runs recurring work, and picks a project up days later “without waiting for a prompt.” The supplier-review example includes building a schedule and workback plan, then prep, meetings, and follow-ups, including reaching out to stakeholders. It is cloud-hosted in the tenant “so it keeps working while you sleep.” It has “its own identity, memory, computer and workspace,” is “built on Microsoft IQ,” and appears in Teams, Outlook, chats, channels, and documents so people can @mention it. The user “set[s] the objective and boundaries.” — [New Copilot, 25 Sep 2026](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)
- The 2 June 2026 Scout announcement, which the Scout page now redirects conceptually to Autopilot, defined Autopilots as “always-on agents that work autonomously, with their own identity, and act on your behalf” without being prompted each time. Scout connected to Teams, Outlook, OneDrive, and SharePoint and to chats, email, calendar, and contacts. The user interacts in Teams and “extend[s] its reach through the desktop app to your browser, local resources, and model context protocol servers.” Examples: schedule meetings across time zones, flag meetings, generate prep materials, block calendar time for deliverables, and spot stalled decisions. It was “powered by OpenClaw open-source technology.” Access at announcement was private preview / Frontier, requiring Frontier enrollment, Intune policy, an opt-in attestation, and a GitHub Copilot license to download the desktop experience. The 25 September post does not repeat the OpenClaw or desktop-app details; it stresses cloud hosting. — [Introducing Microsoft Scout](https://www.microsoft.com/en-us/microsoft-365/blog/2026/06/02/introducing-microsoft-scout-your-always-on-personal-agent/); [New Copilot, 25 Sep 2026](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)
- Also announced 25 September 2026, not yet generally available: Today, a proactive view across mail, calendar, Teams threads, meetings, and tasks, enters private preview in October 2026 in Copilot and later Outlook and Teams. It prepares drafts, proposes schedule changes, and stages follow-ups “waiting for you to send.” @Copilot in a Teams channel, group chat, or meeting uses that container’s shared context and was due in private preview in Teams by the end of September 2026. — [New Copilot, 25 Sep 2026](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)
- Copilot Studio autonomous agents “perceive events, make decisions, and execute tasks independently” using triggers, instructions, and guardrails, and “operate continuously in the background—monitoring data, reacting to conditions, and running workflows at scale,” rather than only answering in a conversation. Examples in the guidance: processing updates, triaging events, initiating follow-ups. They stay inside “scoped permissions, explicit decision boundaries, and auditable processes.” — [Design autonomous agent capabilities](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/autonomous-agents)
- Event triggers (standard harness, generative orchestration required) let an agent act without a user utterance. The trigger sends a payload through a connector; the agent then chooses among actions or topics the author already defined. Documented examples: item created in SharePoint, file created in OneDrive, task completed in Planner, Dataverse row added/modified/deleted, “when a new email arrives,” and a Recurrence trigger (“a set amount of time passed”). Available triggers depend on Power Automate data policies. A trigger does nothing until the agent is published; after publish it reacts automatically. Each payload counts as a billed message; a 10-minute recurrence therefore messages the agent every 10 minutes. — [Event triggers overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-triggers-about)
- Agent flows (standard harness) are deterministic automations: “the same input always produces the same output.” A flow has a trigger and at least one action. Triggers are instant (manual), scheduled, or event-based, including triggers from other agents. Actions include LLM steps (generate text, process documents, run a prompt, call an agent), human-in-the-loop approval or information requests, loops/branches/child flows, and connectors to Microsoft 365, third parties, and custom connectors. Flows that have the “When an agent calls the flow” trigger can be added as tools on an agent. — [Agent flows overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/flows-overview)
- Computer use is a Copilot Studio tool, standard harness, generative orchestration required. The agent drives a Windows computer with a virtual mouse and keyboard: buttons, menus, and text fields on websites and desktop apps, including when no API exists. It is aimed at data entry, invoice processing, and data extraction. The loop is screenshot perception, chain-of-thought reasoning, then click/type/scroll. It runs on a machine the maker configures, not in the user’s interactive coding or chat session. Microsoft says it “works best for autonomous agents, performing tasks in the background.” Models listed as generally available: OpenAI Computer-Using Agent (CUA) and Anthropic Claude Sonnet 4.5. Claude Sonnet 4.6 is standard/experimental; Claude Opus 4.6 is premium/experimental and needs admin-enabled external models. Each step costs 5 Copilot Credits, or 15 on a premium model. — [Computer use](https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use); [Computer use FAQ](https://learn.microsoft.com/en-us/microsoft-copilot-studio/faqs-computer-use)
- Where that computer runs: (1) Hosted browser, preview, Windows 365 for Agents, Microsoft-managed, Microsoft Edge plus built-in Windows apps, not Entra-joined and not Intune-managed, “not recommended for production,” may be throttled. (2) Cloud PC pool, preview, Windows 365 for Agents: auto-scaled Cloud PCs, Entra-joined and Intune-enrolled, work/school account access to Microsoft 365, SharePoint, and Azure. (3) Bring-your-own Windows machine registered in Power Automate, Power Automate for desktop 2.61.132.25266 or later, computer use enabled in machine settings; runs on one machine are queued and executed one at a time. — [Configure where computer use runs](https://learn.microsoft.com/en-us/microsoft-copilot-studio/configure-where-computer-use-runs)
- On a user’s PC, Copilot Actions is an experimental Windows agent that clicks, types, and scrolls in apps and files. The 16 October 2025 Windows security post says a preview for Windows Insiders in Copilot Labs would act on local files, not only the browser. The 17 November 2025 Insider post says app version 1.25112.74 and higher began rolling out on all Insider channels, excluding the EEA: the user chooses “Take Action,” optionally attaches files or folders, and Copilot creates a separate desktop in an Agent Workspace “separate from the interactive user session.” Examples: sort photos, organize Downloads, convert files, extract from a PDF. It is a Copilot Labs experiment; users are told to monitor it and can take over. — [Securing AI agents on Windows](https://blogs.windows.com/windowsexperience/2025/10/16/securing-ai-agents-on-windows/); [Copilot Actions Insider rollout](https://blogs.windows.com/windows-insider/2025/11/17/copilot-on-windows-copilot-actions-begins-rolling-out-to-windows-insiders/)
- Foundry autopilot agents (public preview, announced on the Foundry blog alongside Build-period distribution features) “operate autonomously using their own identity” and have user accounts with a productivity license: their own email, calendar, OneDrive, Teams access, and a place in the org chart. They are meant for shared spaces such as Teams group chats, not only 1:1 chat. The Workstream Manager sample lives in Teams group chats, tracks commitments, summarizes the workstream, follows up on overdue work, and is pre-wired with Word, Excel, Outlook mail, calendar, and OneDrive/SharePoint tools. In group chats it replies when @mentioned or clearly addressed. Publishing any Foundry agent into Microsoft 365 Copilot and Teams was described as “generally available next month” from that post, with an interaction model of goal, ongoing execution, checkpoints, and collaboration rather than only prompt-then-response. — [Foundry enterprise agent distribution](https://devblogs.microsoft.com/foundry/from-building-agents-to-working-with-them-enterprise-agent-distribution-in-microsoft-foundry/)
- Copilot Studio multi-agent: generative orchestration lets one agent call others. Inline/child agents are topics inside the same agent and share the parent’s context. Connected agents are separate agents with their own orchestration, tools, and knowledge; the parent delegates. Connected agents can be Foundry, Fabric, Microsoft 365 Agents SDK (public preview per the patterns article’s related links), or Agent2Agent (A2A). Foundry agents can call remote A2A agents and, in public preview, expose themselves as A2A endpoints authenticated with Entra ID. — [Multi-agent orchestration patterns](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/multi-agent-patterns); [Foundry enterprise agent distribution](https://devblogs.microsoft.com/foundry/from-building-agents-to-working-with-them-enterprise-agent-distribution-in-microsoft-foundry/)

### Inferences
- The product a person would use as a general, unattended work agent in late September 2026 is Copilot Autopilot (ex-Scout), still private preview, plus Foundry autopilot agents in public preview. Researcher and ordinary Copilot chat still wait for a person to ask. Copilot Studio is the supported way to run unattended work today against mail, files, and schedules, but the agent only does actions the maker pre-authored.
- “Own computer” for Autopilot (September 2026) is stated as cloud-hosted inside the tenant. That is a different runtime from Windows Copilot Actions, which uses a local agent workspace on the user’s PC, and from Copilot Studio computer use, which uses a hosted browser, a Cloud PC pool, or a registered Windows machine.

- Analyst’s capabilities, beyond “better suited for Excel” and admin block alongside Researcher, were not verified from a dedicated page.
- The agent-flow 100-second tool-response limit was seen in search snippets of a related Learn page that was not opened, so it is omitted from cited findings.
- No opened page states whether September 2026 Autopilot still embeds OpenClaw or still ships the Scout desktop app.

## How do they get permission to act on mail, calendar, files, and the desktop?

### Takeaway
Microsoft 365 Copilot and its declarative agents act as the signed-in user and cannot exceed that user’s Graph permissions. Copilot Studio unattended runs instead use the maker’s connection credentials unless the tool is set to end-user credentials, which blocks true autonomy. Autopilot/Scout and Foundry autopilot agents are the exception that gets its own Entra identity and, for Foundry, its own mailbox and calendar. Desktop action is a separate grant: a Windows agent account and explicit folder access for Copilot Actions, or a machine connection plus stored site credentials for computer use.

### Cited Findings
- Microsoft Graph “honors the user identity-based access boundary,” so Copilot grounding, including data ingested by a synced Copilot connector, “only accesses content that the current user is authorized to access.” “Agents respect existing Microsoft 365 permissions. If a user does not have access to a SharePoint site, Teams channel, or Outlook mailbox, the agent cannot retrieve or display content from those sources.” “Agents do not introduce new privileges.” Sensitivity labels on SharePoint and OneDrive files are respected. Content in SharePoint, Exchange, and Teams stays under those services’ DLP, retention, and compliance policies. Admins enable, disable, assign, block, or remove agents from Microsoft 365 admin center > Copilot > Agents, and can limit sharing to everyone, specific users or groups, or nobody. — [Data, Privacy, and Security for Copilot extensibility](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/data-privacy-security)
- Researcher “respects the same permissions, policies, and compliance” as Microsoft 365 Copilot, adheres to DLP, is not trained on tenant data, and “doesn’t send user data” or file attachments to OpenAI. Admins cannot turn it off merely by disabling Copilot agents; it stays under Tools. Admins can still block Researcher and Analyst. Users cannot disable, remove, or unpin Researcher. Web content is all-or-nothing via the tenant web-search toggle; there is no per-site allow/block list. — [Researcher agent](https://learn.microsoft.com/en-us/microsoft-365/copilot/researcher-agent); [Researcher FAQ](https://learn.microsoft.com/en-us/microsoft-365/copilot/faq-researcher)
- Copilot Chat billing gate: declarative agents grounded only in instructions and public websites are included and on by default. Agents that access shared tenant data such as SharePoint or Graph connector content are metered and “off by default” for Copilot Chat users until an admin sets up Copilot Studio pay-as-you-go or prepaid capacity. No extra enablement is required for users who already have a Microsoft Copilot license. — [Agents for Microsoft Copilot Chat](https://learn.microsoft.com/en-us/copilot/agents)
- Event triggers “can only use the agent maker’s credentials.” For an agent to run autonomously, “each action must be configured with working maker authentication that doesn’t require user input.” If authentication is missing, the agent asks the user and, if it cannot continue, the session stops. Publishing warns that users of the agent might access data or perform actions with the author’s credentials. Payloads can carry sensitive data into later actions (the doc’s example is incoming email copied into Dataverse). Admins can block event triggers with data policies. Triggers can be added only where solution-aware cloud flow sharing is on. — [Event triggers overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-triggers-about)
- Autonomous-agent guidance tells makers to use least privilege, validate trigger authenticity (sender checks or keywords on email, and authentication so only authorized callers invoke the agent), keep a human in the loop before sensitive actions, and log triggers, decisions, and actions. — [Design autonomous agent capabilities](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/autonomous-agents)
- Agent-flow actions include “Human in the loop” approval requests and requests for information that pause the flow until a person responds. — [Agent flows overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/flows-overview)
- Computer-use credentials: default is maker-provided credentials, “suitable for autonomous agents,” with an explicit warning that anyone the agent is shared with “can act with the original author’s access on the configured machine.” Alternatively, end-user credentials require each conversational user to have their own machine credentials. Sign-in secrets for sites and desktop apps can be stored in Power Platform internal storage or an Azure Key Vault the maker names. An optional allow list limits which sites and desktop apps the model may act on; it does not stop the model from opening other sites, only from interacting once they are open. Enforce HTTPS blocks `http://` sites. Human supervision emails an Outlook reviewer if the run detects potentially harmful instructions; if nobody answers before the response-time limit, the run stops. The FAQ says those clarification requests are probabilistic and “shouldn’t [be] rel[ied] on … as a safety fail-safe.” — [Computer use](https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use); [Computer use FAQ](https://learn.microsoft.com/en-us/microsoft-copilot-studio/faqs-computer-use)
- New Copilot Studio agents get a Microsoft Entra Agent ID (service principal, Agent subtype). Agents created before Entra Agent ID in May 2026 keep legacy app registrations until a future migration. Agent Builder agents in Microsoft 365 Copilot “don’t use or require” an app registration or Agent ID. Copilot Studio creates the identity; makers cannot bring their own. The owner is added as a sponsor on Agent IDs. No one in the tenant, including administrators, can mint tokens for an Entra Agent ID; a Microsoft-owned blueprint does. On publish, the Agent ID receives API permissions that represent configured Power Platform connectors, such as `Operations.Execute.All` or per-operation scopes, not Graph scopes like `Mail.Read`. The connector runtime re-checks advanced connector policies and data-loss-prevention policies. Conditional Access on the agent identity is enforced only when the agent runs in Teams; other channels still use the Power Platform connector auth flow. Custom connectors, MCP servers, and REST API tools do not add API permissions to the Agent ID. Deleting the agent deletes the identity. — [App registration, agent identities, and authentication](https://learn.microsoft.com/en-us/microsoft-copilot-studio/govern-agents-identities-overview)
- Scout: “Every agent operates under its own governed Entra identity, not a shared, anonymous service account.” Credentials are “scoped to the task,” redacted from logs, and “agents can only reach the resources and destinations you’ve approved.” “Sensitive actions can require a human to sign off before they proceed.” Purview sensitivity labels and DLP “are enforced in the moment, before anything is sent or written.” — [Introducing Microsoft Scout](https://www.microsoft.com/en-us/microsoft-365/blog/2026/06/02/introducing-microsoft-scout-your-always-on-personal-agent/)
- September 2026 Autopilot: lives in the tenant with its own identity; @mention “like a colleague, with permissions, audit and governance behind it.” The post does not spell out mailbox rights, approval prompts, or whether the identity is an Entra Agent ID versus a licensed user account. — [New Copilot, 25 Sep 2026](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)
- Foundry autopilot agents have both an Entra agent identity and a user account with a productivity license (email, calendar, OneDrive, Teams, org chart). Every Foundry agent is registered in Microsoft Agent 365 at creation. Admins review and approve access before org-wide publish. Incoming and outgoing A2A calls are authenticated with Entra ID and are not anonymous. The Workstream Manager sample is manager-gated: only the manager can talk to it until they add users; in group chats every participant must be approved. — [Foundry enterprise agent distribution](https://devblogs.microsoft.com/foundry/from-building-agents-to-working-with-them-enterprise-agent-distribution-in-microsoft-foundry/)
- Windows Copilot Actions is off until the user enables Settings > System > AI components > Agent tools > Experimental agentic features. Agents get a separate standard local account, provisioned only when the agent workspace is enabled, and run as that account rather than the interactive user. During the experimental preview the agent can access known folders (Documents, Downloads, Desktop, Pictures) and resources already available to all local accounts; anything else needs user authorization. ACLs still apply. Users can monitor and take over. “When sensitive actions or important decisions are involved, Copilot Actions may request additional user approval.” Entra and Microsoft account identity support for these Windows agents was described as “coming soon” on 16 October 2025. The workspace is a separate desktop with limited visibility into the user’s own desktop. — [Securing AI agents on Windows](https://blogs.windows.com/windowsexperience/2025/10/16/securing-ai-agents-on-windows/)
- Declarative-agent warning: if a custom action returns untrusted content (emails, support tickets), an attacker can plant instructions that make the agent answer wrongly or invoke actions. Microsoft’s mitigation guidance is to allow only trusted knowledge and REST APIs, and not to let an agent perform sensitive operations on untrusted data without human intervention. Copilot Studio admins govern which connectors makers can use for knowledge and actions. Publishing an agent to the org catalog requires admin approval. — [Data, Privacy, and Security for Copilot extensibility](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/data-privacy-security)

### Inferences
- There are three different permission stories, and they should not be collapsed. In-chat Copilot and Researcher borrow the user’s mailbox and files. Copilot Studio autonomy borrows the maker’s connections and can leak that authority to everyone who can talk to the published agent. Autopilot, Scout, and Foundry autopilot agents are designed to be their own directory actors, with Foundry going further and giving the agent a licensed mailbox, calendar, and Teams presence.
- A human approval step is available but not automatic: makers must add it in Copilot Studio, Scout says sensitive actions “can” require sign-off, computer-use supervision is explicitly not a guarantee, and Windows Copilot Actions “may” ask.

### Gaps
- No opened page lists the Graph scopes or mailbox rights of the September 2026 Copilot Autopilot, or whether its “own identity” is an Entra Agent ID, an Entra agent user, or both.
- No opened page describes a per-action consent prompt inside ordinary Microsoft 365 Copilot chat when the model reads mail the user already can read.
- The October 2025 statement that Entra/MSA support for Windows agent accounts was “coming soon” was not rechecked against a 2026 Learn article, so current status of that identity support is unverified.
- Conditional Access and connector-scope behavior for Copilot Studio was documented for Teams versus other channels; how that interacts with Autopilot’s @mention in Outlook was not documented on any page opened.

## What is the connector / plugin / skill model?

### Takeaway
Microsoft does not use one extension type. Microsoft 365 Copilot is growing a plugin registry that bundles skills, connectors, and other capabilities under IT approval. Copilot Studio agents call Power Platform connectors, agent flows, computer use, child agents, and optional per-user memory. Synced connectors copy data into Microsoft Graph under ACLs; the agent itself does not gain rights the user or maker lacks. “Skills” in the September 2026 Copilot announcement are reusable role workflows inside Office apps, which is a different feature from Copilot Studio’s authenticated skill endpoints.

### Cited Findings
- Extensibility options documented for Microsoft 365 Copilot include declarative agents (custom instructions, grounding knowledge, and actions described as REST APIs) and synced Microsoft 365 Copilot connectors. Synced connector data “flows into Microsoft Graph” and stays in the tenant. Item visibility is an ACL tied to an Entra user or group, or an external group. For API-plugin style agents, “external data stays within your app; it doesn’t flow into Microsoft Graph” and is not used to train Copilot LLMs; Copilot sends a search query built from the prompt, conversation history, and Microsoft 365 data the user can access. Prompts, responses, and Graph data are not used to train foundation LLMs. Admins control integrated apps per user or group, and Copilot Studio admins govern connectors used as knowledge or custom actions. Copilot only searches agents and connectors an admin has enabled. — [Data, Privacy, and Security for Copilot extensibility](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/data-privacy-security)
- Researcher can fetch Graph connector data. The FAQ says “future updates will allow connector configuration,” which implies configuration was not fully available when that FAQ was written (page metadata date 31 October 2025; page updated 18 August 2026). Web access is the tenant Bing toggle only. — [Researcher FAQ](https://learn.microsoft.com/en-us/microsoft-365/copilot/faq-researcher)
- 25 September 2026: “Plugins extend what Copilot can do, bringing together skills, connectors and other capabilities.” A “new plugin registry” was “rolling out now and generally available across surfaces in the coming weeks,” combining Microsoft, partner, and custom plugins. IT approves and manages plugins centrally; developers publish once. Separately, “across Microsoft 365, Skills help bring specialized expertise directly into the apps, like financial skills in Excel and legal skills in Word,” and organizations can scale “reusable, role-specific workflows.” Copilot is also grounded in Microsoft IQ; Fabric IQ (Power BI semantic models) is generally available for Chat and Cowork; Dynamics 365 and Power Platform grounding was rolling out over the following month in public preview. Code runs in a sandboxed, tenant-hosted environment via Copilot Managed Runtime (preview), shared with apps built in Cowork, Code, and Copilot Studio. — [New Copilot, 25 Sep 2026](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)
- Copilot Studio tools and actions, from pages opened: event-trigger connector library; agent-flow connectors (Microsoft 365, third-party, custom) plus AI actions and human-review actions; computer use as a tool with natural-language instructions, inputs, a machine, a connection, and stored credentials; child and connected agents treated by the parent as tools with descriptions. Generative orchestration must be on for event triggers and computer use. The agent cannot invent a new action at runtime; the author must have defined the action or topic. — [Event triggers overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-triggers-about); [Agent flows overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/flows-overview); [Computer use](https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use); [Multi-agent patterns](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/multi-agent-patterns)
- On publish, first-party and certified Power Platform connectors used by an agent show up as API permissions on its Entra Agent ID. Custom connectors, MCP servers, and REST tools do not. — [Agent identities](https://learn.microsoft.com/en-us/microsoft-copilot-studio/govern-agents-identities-overview)
- Memory in Copilot Studio is a preview tied to the GitHub Copilot harness, not described as part of the standard harness. The maker toggles it per agent. Each user gets a private folder in Microsoft-managed storage. The agent captures preferences and context, stores them as files, and reads them later. Makers and other users cannot see those memories. The user can ask the agent what it remembers, update or forget an item, or open a memory portal and delete all memories. Memories are deleted after 28 days without interaction. Memory is disabled in group chats and Teams channels. Turning the toggle off stops use but does not delete stored memories. The first response in a new channel includes a portal link. — [Memory (preview)](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/memory-overview)
- Researcher “memory” is listed as “to be released soon.” Agent-to-agent conversations for Researcher are also “to be released soon.” Researcher cannot be extended in Copilot Studio: “you can’t modify Researcher’s predefined logic or content.” — [Researcher FAQ](https://learn.microsoft.com/en-us/microsoft-365/copilot/faq-researcher)
- Scout’s memory story is Work IQ: it “builds context … learning how you work, what you care about, and what needs to happen next.” The desktop preview could attach MCP servers. September 2026 Autopilot is said to have “its own … memory” and to be “built on Microsoft IQ,” without a storage or retention description. — [Introducing Microsoft Scout](https://www.microsoft.com/en-us/microsoft-365/blog/2026/06/02/introducing-microsoft-scout-your-always-on-personal-agent/); [New Copilot, 25 Sep 2026](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)
- Foundry Workstream Manager ships with built-in Work IQ tools for Word, Excel, Outlook mail, calendar, and OneDrive/SharePoint, and can be pointed at extra sources such as SharePoint, specs, and Azure DevOps. Foundry agents publish into Copilot and Teams through a governed pipeline and call each other over A2A. — [Foundry enterprise agent distribution](https://devblogs.microsoft.com/foundry/from-building-agents-to-working-with-them-enterprise-agent-distribution-in-microsoft-foundry/)
- Multi-agent handoff rules that makers are told to follow: one speaker to the user per turn unless a direct child reply is deliberate; tell subagents explicitly not to reply to the user; use non-overlapping knowledge sources; write distinct descriptions because the parent routes on them; a connected agent has a context-inclusion setting and does not automatically get the parent’s history, while an inline child always does. Connected agents can hold privileges the parent lacks, so a call can bypass a parent restriction unless the maker blocks it. — [Multi-agent patterns](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/multi-agent-patterns)
- The identity article mentions Copilot Studio obtaining an agent-identity token and presenting it when “validating or invoking a skill.” That is an authenticated call to a skill endpoint, not the Office “Skills” in the September Copilot announcement. The skills-overview page itself was not opened. — [Agent identities](https://learn.microsoft.com/en-us/microsoft-copilot-studio/govern-agents-identities-overview)

### Inferences
- “Plugin” in the September 2026 Copilot app is an IT-catalog wrapper around skills plus connectors. “Connector” in Copilot Studio is still a Power Platform connection, often running as the maker. “Skill” is overloaded: Office role workflows in the Copilot announcement, versus a token-authenticated skill endpoint in Copilot Studio.
- Per-user file memory is a Copilot Studio (GitHub Copilot harness) feature with a 28-day idle expiry and is explicitly off in Teams channels, so it is not the memory of a Teams-resident Autopilot.

### Gaps
- The plugin-registry admin model (who can install, whether plugins can write mail, consent UI) is only described at announcement level.
- No opened page maps Microsoft 365 “Skills” to files, manifests, or approval rules.
- Copilot Studio skills-overview was not opened, so skill discovery, parameters, and approval behavior are unknown beyond the token note.
- Federated versus synced Copilot connectors were visible in search snippets and not opened; only the synced-connector path is cited.
- Autopilot’s memory implementation (per user, per agent, retention, tenant admin visibility) is not specified.

## What limitations do Microsoft’s own docs emphasize?

### Takeaway
Microsoft’s own docs stress that unattended agents are preview or capacity-limited, that GUI agents are unreliable and unsafe on sensitive transactions, that trigger-based agents run as the maker and only among pre-built actions, and that first-party Researcher cannot be customized, has a 25-query monthly cap, and has no per-site web filter. Human confirmation is repeatedly described as something the product will not guarantee by itself.

### Cited Findings
- Researcher: 25 queries per user per month. No per-website allow/block list, only the tenant web-search toggle. If web search is off, answers reflect training data “up to 2024.” Cannot process images in input documents. Cannot generate PowerPoint or PDFs yet (“to be released soon”). No memory yet, no agent-to-agent yet, no report-length control yet, not customizable in Copilot Studio. Not in sovereign clouds yet (“to be released soon”). Users cannot disable it. No admin report of Researcher or Analyst usage; session content is not e-discoverable unless the user submits feedback that includes it. Admins can see usage metrics but not conversation content, with that feedback exception. Model choice exists inside the Researcher agent; @Researcher from ordinary chat defaults to auto and the picker is disabled. — [Researcher FAQ](https://learn.microsoft.com/en-us/microsoft-365/copilot/faq-researcher)
- Event triggers: only the maker’s credentials; users of a published agent may inherit that access; the publish dialog warns the maker. The agent does not create actions on the fly. Docs advise calling fewer than 15 actions or topics in one sequence because longer sequences “can struggle to run them reliably.” Frequent or indefinite recurrence can hit quota and get throttled; admins can block triggers. Trigger payloads can leak sensitive data into other systems. `Activity.Text` can be empty when a knowledge source is used or when some Teams activities fire; `LastMessage.Text` is the documented fallback. Some connectors fail repeatedly and the doc’s workaround is to wrap them in a Power Automate flow. Instruction conflicts between the agent and the payload “can cause an error or unexpected results.” — [Event triggers overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-triggers-about)
- Agent flows: when prepaid Copilot Studio capacity is exhausted, new runs are blocked until capacity returns. In-flight runs finish. Microsoft 365 Copilot licensed users and test runs are exempt. Natural-language flow creation still has to be edited into a deterministic path; the product claim is reliability from fixed steps, not open-ended planning. — [Agent flows overview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/flows-overview)
- Computer use FAQ limitations: performance varies by task and UI; layout, delay, and unexpected dialogs change outcomes; dropdowns, date pickers, and custom widgets are hard; the agent can loop or stall; complex graphics or intricate text are less reliable. Not intended for hiring, healthcare, or finance scoring, financial transactions, spam or misinformation, or sharing data outside the organization without authorization. Prompt injection can arrive in screenshots or pages. Human supervision “might not trigger” when a person would want a pause, and “don’t guarantee enforcement of your defined rules.” Access control does not prevent opening a non-allow-listed site, only acting on it. Maker-credential sharing means every user of a shared agent acts as the author on that machine. Password fill is not supported for some app types (Electron, Java, Unity, games, command lines, Citrix, and other virtualized environments are called out as possibly unsupported). Hosted browser is preview, not for production, not Entra-joined, and may be throttled. Cloud PC pool is also marked preview. One machine runs jobs strictly in a queue. Anthropic models need an admin external-model switch. — [Computer use](https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use); [Computer use FAQ](https://learn.microsoft.com/en-us/microsoft-copilot-studio/faqs-computer-use); [Configure where computer use runs](https://learn.microsoft.com/en-us/microsoft-copilot-studio/configure-where-computer-use-runs)
- Autonomous-agent guidance is mostly constraint: narrow scope, least privilege, authenticate triggers, human oversight for high-stakes actions, audit logs, staged rollout. It does not claim the platform enforces those boundaries unless the maker configures them. — [Design autonomous agent capabilities](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/autonomous-agents)
- Multi-agent docs emphasize extra latency, duplicate user-facing messages if instructions are soft, accidental privilege bypass through a more powerful child, and history that is not passed to a connected agent unless the context-inclusion setting says so. — [Multi-agent patterns](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/multi-agent-patterns)
- Copilot Studio memory: production-ready preview; 28-day deletion; off in group chats and Teams channels; invisible to the maker; off switch does not delete data; GitHub Copilot harness only. — [Memory (preview)](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/memory-overview)
- Identity limits: Agent Builder agents have no Entra Agent ID. Legacy app registrations have no connector scopes. Conditional Access on connector scopes applies only in Teams today. Tenant directory quota can block agent creation (default 50,000 directory objects, or 300,000 with a verified domain; agent identities cannot use more than 95% of quota; new tenants capped at 600 objects for two days). Custom connectors, MCP, and REST tools are invisible as Entra API permissions. — [Agent identities](https://learn.microsoft.com/en-us/microsoft-copilot-studio/govern-agents-identities-overview)
- Windows Copilot Actions: experimental, off by default, mistakes and “challenges with complex interfaces,” cross-prompt injection called out as a way UI or documents can override instructions, limited default folders, separate local account rather than the user’s Entra identity (Entra/MSA support was still “coming soon” in the October 2025 post), EEA excluded from the November 2025 Insider rollout, and users are told to watch the run. — [Securing AI agents on Windows](https://blogs.windows.com/windowsexperience/2025/10/16/securing-ai-agents-on-windows/); [Copilot Actions Insider rollout](https://blogs.windows.com/windows-insider/2025/11/17/copilot-on-windows-copilot-actions-begins-rolling-out-to-windows-insiders/)
- Autopilot itself, as of 25 September 2026, is private preview at month’s end, billed on usage rather than the Copilot user license, and the announcement does not publish limits, SLAs, or a control matrix. Scout’s earlier availability required Frontier, Intune policy, attestation, and a GitHub Copilot license. Today and Teams @Copilot were still “private preview,” not shipping features, at announcement. — [New Copilot, 25 Sep 2026](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/); [Introducing Microsoft Scout](https://www.microsoft.com/en-us/microsoft-365/blog/2026/06/02/introducing-microsoft-scout-your-always-on-personal-agent/)
- Foundry autopilot agents and incoming A2A were public preview. The Workstream Manager’s group-chat behavior is mention-gated and manager-approved; that is a sample, not a platform guarantee for every autopilot agent. — [Foundry enterprise agent distribution](https://devblogs.microsoft.com/foundry/from-building-agents-to-working-with-them-enterprise-agent-distribution-in-microsoft-foundry/)
- Untrusted email or tickets used as declarative-agent knowledge can redirect the agent, and the documented defense is human review plus not granting sensitive actions, not a platform claim that injection is solved. — [Data, Privacy, and Security for Copilot extensibility](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/data-privacy-security)

### Inferences
- The durable, documented way to run work with nobody sitting in a session is still Copilot Studio triggers and flows, with the maker’s identity and a closed action list. The general “teammate” that watches mail and Teams on its own identity is real as a named product (Autopilot, ex-Scout; Foundry autopilot agents) but was still preview on 29 September 2026, and its limits are not in Learn.
- Microsoft’s strongest self-stated limits on computer use are reliability (UI controls, loops) and intent (no financial transactions, no high-stakes scoring), plus the warning that supervision emails are not a safety control.

### Gaps
- No opened Learn page gives quota, data-retention, or admin-disable steps for Copilot Autopilot after the 25 September 2026 rename.
- Analyst limits were not documented on any page opened except the shared admin block and the note that it is the better Excel tool.
- Whether Windows Copilot Actions left Insider preview, expanded beyond the EEA, or gained Entra agent accounts after November 2025 was not re-verified.
- Computer-use general-availability date was on a release-plan page that was not opened. The computer-use article’s model table does mark CUA and Claude Sonnet 4.5 as generally available, while hosted browser and Cloud PC pool sections are still labeled preview.
