## What is implemented and wired to the user?

### Takeaway
The harness is a working, user-facing product: four providers, a streaming tool loop with approvals, a documented tool set (files, shell, web, memory, skills, subagents, questions, background processes), MCP, hooks, compaction, TUI, `--print`, JSON-RPC `--headless`, and a library facade. Several of those features are verified by tests and by live runs on Ollama and xAI, not on api.openai.com or Anthropic, and the interactive TUI has not had a human check since v2.

### Cited Findings
- **Providers wired by config.** User guide “Providers and models”: `ollama` (default `http://localhost:11434`, no key), `openai` (Chat Completions, `OPENAI_API_KEY`, `https://api.openai.com/v1`), `anthropic` (Messages API, `ANTHROPIC_API_KEY`), `openai_compatible` (any Chat Completions server; `ARBE_BASE_URL` required, key optional). README “Build and run” shows the same four launch lines. Plan P2.5: Azure deployment-path / `api-key` scheme is not covered. Plan open question 1: OpenAI Responses API was not chosen; Chat Completions only.
- **Streaming is the only model path.** Plan P3.2: every round uses `ModelProvider::stream`; events include `TextDelta` / `ThinkingDelta` / `ToolUseInputDelta`. Plan P2.1: retries only before the first event; mid-stream failure is an error, not a silent retry. User guide `ARBE_MAX_RETRIES` (default 4): retries rate limits, 500/502/503/529, timeouts, transient network; honors `Retry-After`; backoff 1s–60s; `0` disables. A stream that ends without the provider’s end marker is `ProviderError::Network`, not a complete answer (plan P7.1).
- **Thinking.** User guide “Thinking”: Anthropic with `ARBE_THINKING_BUDGET`, and OpenAI-compatible servers that stream `reasoning_content` (xAI, DeepSeek, vLLM), shown as a collapsed `[thinking]` line; `Ctrl+T` expands; resumed sessions do not show earlier thinking. Plan P2.4: Anthropic extended thinking with signature round-trip; only signed thinking is echoed; redacted thinking is `Opaque`; thinking budget is added on top of `max_tokens` and drops temperature. Plan progress log 2026-09-29: profile switch away from Anthropic drops signed thinking blocks (user guide “Switching models with profiles” says the same).
- **Images.** Plan P1.1: `ContentBlock` includes `Image`; token estimate is a flat 1,600 per image; OpenAI uses data-URL parts, Ollama base64 `images`. Plan P3.7: `read_file` returns PNG/JPEG/GIF/WebP ≤ 3.75 MB as an attachment when `capabilities(model).vision`, otherwise a one-line note. Anthropic accepts images inside `tool_result`; OpenAI-compatible and Ollama tool messages are text-only, so those adapters put images in a following user message. Live: grok-4.7 named a PNG’s colour. User guide builtin-tools table matches the formats and size.
- **Text tool-call fallback is Ollama-only in code.** User guide Ollama row: if a reply is *only* JSON tool calls to offered tools, they are treated as real calls, and such a reply is shown once complete rather than token-by-token. `crates/arbe-providers/src/ollama.rs` holds `TextToolCallFilter`; `text_tool_calls.rs` is not referenced from the OpenAI adapter. `CLAUDE.md` says the filter is “wired into Ollama; reusable for `openai_compatible`” — reusable, not wired. Ollama also retries without tools when the model returns “does not support tools” (user guide; plan P0.3 / P2.3).
- **Prompt cache is Anthropic-only, and cache hits were not measured live.** Plan P2.4 and `crates/arbe-providers/src/anthropic.rs` module comment: `cache_control` breakpoints on the last system block, on messages flagged `cache_breakpoint`, and on the final message. Plan P5.4: context order is system → global → skills → memory → summary → history → user; tools sorted by name; truncation cuts quantized to multiples of 4 turns when ≥ 8 remain, so the prefix stays stable. “Not measured against a live provider's cache-hit counters yet (P7.2).” Usage fields include `cache_read_tokens` / `cache_write_tokens` (user guide `meta.json`). Optional prices `cache_read_price` / `cache_*_price` exist for cost math (user guide “Costs”; plan P6.8). No finding that OpenAI prompt caching is implemented.
- **Catalog and output cap.** User guide context-window table: `gpt-5*` 400k, `gpt-4.1*` 1,047,576, `gpt-4o*` 128k, `o1*`/`o3*`/`o4*` 200k, `claude-*` 200k, other OpenAI/compatible 128k, Ollama 8,192. Plan P2.6: longest-prefix match; “No `max_output_tokens` yet.” User guide: “The maximum response length is fixed at 4096 output tokens.” Token display starts as ~4 chars/token and is calibrated from reported input tokens (user guide; plan P2.7 `TokenCalibration`, EMA clamped [0.5, 3.0]). Provider-native count endpoint “is not done.”
- **Live verification vs implementation.** Plan status table: P2 is `In progress`, 9/9 tasks done, “Not Done yet” because live OpenAI and Anthropic runs are missing. `docs/v2-status.md` P2: Ollama live (`qwen2.5-coder:7b`, `llama3.2:3b`); OpenAI wire format live only via `openai_compatible` against xAI (`grok-4.7`, `grok-4.20-0309-reasoning`), **not api.openai.com**; Anthropic fixture + `crates/arbe-providers/tests/http.rs` only. Plan P2.9: stream fixtures are “hand-written from the documented wire formats, not captured from real traffic.” Plan progress log 2026-09-29: 12/12 `live_agent` tests on grok-4.7 (files, execute fix loop, denials, resume, memory, on-demand skills, nested `AGENTS.md`, compaction, cancellation, general profile, MCP, hook veto).
- **Agent loop, wired.** Plan P3.1–P3.6 marked done: one turn at a time (`HarnessError::Busy`); streaming rounds; `in_flight.jsonl` write-ahead then commit to `turns.jsonl`; resume recovers an interrupted turn; approvals one-at-a-time then parallel execution for `parallel_safe` tools; `write_file`, `edit_file`, `execute`, `todo_write` are not parallel-safe (`crates/arbe-tools/src/builtin/mod.rs` test). User guide “Several calls at once” lists read-only tools that run together: `read_file`, `list_dir`, `glob`, `grep`. Cancel (`Esc` / `Agent::cancel_turn`) persists partial output as `StopReason::Cancelled` and closes unmatched tool uses. Guards: `ARBE_MAX_TOOL_ROUNDS` default 50, optional `ARBE_MAX_TURN_TOKENS`, identical tool rounds stop on the third (`StopReason::RepeatedToolCall`); user guide “Stuck loops.” Plan P3.6 also says a per-turn *cost* ceiling was in the task wording; the *Done* note only names token and round guards, not a cost ceiling.
- **Dangling tool results.** `crates/arbe-runtime/src/agent/turn.rs` `close_dangling_tool_uses`: every tool call without a result gets an error result “not executed: the turn ended before this tool call ran”; matching is positional because some servers reuse ids such as `call_0`. Plan progress log 2026-09-28 records that id-global matching was a bug and was fixed. User guide Sessions: crash recovery marks the turn interrupted; “At most the reply that was streaming at that moment is lost.”
- **Tools the user guide documents as present** (“Builtin tools”): `read_file`, `list_dir`, `glob`, `grep`, `remember`, `load_skill` (only when skills are on demand), `task` (not in `general`), `ask_user`, `web_fetch`, `web_search` (only if `[web.search]` is set), `todo_write`, `write_file`, `edit_file`, `execute`, `process_output`, `process_kill`. `crates/arbe-tools/src/builtin/mod.rs` `TOOL_NAMES` registers the filesystem/shell/todo/web_fetch set only. `remember`, `load_skill`, `task`, and `ask_user` are runtime tools (`agent/memory.rs`, `agent/skills.rs`, `agent/subagent.rs`, `agent/ask.rs` per the plan). `web_search` is in `builtin/web.rs` and in `GENERAL_PROFILE_TOOLS` (`crates/arbe-runtime/src/config/mod.rs` lines 125–131: `todo_write`, `remember`, `ask_user`, `web_fetch`, `web_search`) but is not in `TOOL_NAMES` / `register_all` — it is registered when search is configured (plan P6.7). Coding profile: “all builtin tools” (user guide Profiles).
- **Limits called out next to those tools (user guide).** `list_dir` max 1,000 entries; `glob` max 2,000; `grep` max 500; skips `.git`, `target`, `node_modules`, `.venv`. `web_fetch`: http/https, default 20,000 chars (max 100,000), reads at most 3 MB, binaries refused. `todo_write`: replaces the whole list, at most one `in_progress`, at most 200 items, memory only. `execute`: `cmd /C` on Windows, `sh -c` elsewhere, timeout default 30s max 300s, **not sandboxed**. Tool output to the model capped at `ARBE_MAX_TOOL_OUTPUT_CHARS` default 50,000 (head+tail). Transcript shows at most the first 500 characters of a result. Background: handle `bg-N`, 256 KB kept, 32 KB per read, max 16 per session, killed when the session ends (plan P6.4; tested on Windows and Linux; live grok-4.7 `python -m http.server`).
- **Approvals, rules, path guard, redaction, trust — all user-facing.** User guide “Approvals”: modes `always_prompt` (default), `allowlist_auto`, `denylist_block`, `dry_run_only`; deny rules apply in every mode. High-risk (`execute`, and MCP tools the server marks destructive) auto-approve only via a patterned rule such as `execute(cargo test*)`, never a bare name. Session `a` on a high-risk call is an exact literal command. `process_output` and `ask_user` skip the human prompt (`requires_approval() = false`) but still pass the gate (plan P6.5). Path sandbox: user guide “Sandboxing” — file tools refuse paths outside the workdir, including `..`. Plan open question 3: OS sandbox for `execute` (containers, Seatbelt, landlock, Windows job objects) is out of scope for v2. Redaction: plan P4.9 `arbe_runtime::redact::Redactor` scrubs API key, MCP bearer tokens, credential-named header values, and secret-named env vars from tool output before the model, `turns.jsonl`, and the TUI; model-generated text is not redacted. User guide: search key is redacted. Trust: plan progress log 2026-09-28 and user guide “Trusted projects” — untrusted `<workdir>/.arbe/config.toml` loses provider endpoint/key, approval, MCP, hooks, and `[web.search]` (plan P6.7); a project cannot trust itself. Keys are env names or `provider.api_key_command`, not a plaintext `api_key` (plan P4.1, P4.9).
- **MCP, hooks, skills, instructions — wired.** User guide MCP: stdio and streamable HTTP; tools named `<server>__<tool>`; background connect; `tools/list_changed` at next message; stdio restart on next call; stderr at `~/.arbe/logs/mcp/<name>.log`. Plan P4.4 “Not done”: standalone GET stream for server-initiated HTTP messages; user guide “HTTP limitation” matches. Plan P4.5: MCP images become placeholders, not real images (“A tool's result is shown to the model as text. Images a tool returns appear as `[image: <type>]`” — user guide). Hooks: command hooks in config; only `before_tool_execute` can rewrite arguments or veto, and it runs before the approval dialog (user guide Hooks). Eight phases are listed, including `on_approval_requested`. Skills: global `~/.arbe/skills/` and `<workdir>/.arbe/skills/`, non-recursive, project overrides global on name; `skills.mode` `on_demand` (default) vs `always`; `load_skill` added even if the profile tool list omits it (user guide; plan P4.6). Instructions: global `~/.arbe/instructions/agent.md`; project root `agent.md` else `CLAUDE.md`, no parent walk; each capped at 8,000 chars; re-read every message (user guide). Nested: an `AGENTS.md`, `agent.md`, or `CLAUDE.md` under a subdirectory is appended to the first successful path-tool result that touches that folder, once per session (user guide; plan P5.5 `agent/nested.rs`). Not the whole-tree precedence model in `docs/todo.md`.
- **Memory, pruning, compaction — wired.** User guide Memory: `remember` appends one line to global or project `memory.md`; both files are included every request, capped at 8,000 chars. Plan P5.6: project id is `<folder>-<fnv32>`. User guide “Long sessions” order: (1) old tool results shortened to a one-line note, including inside a long turn, newest unread results kept whole; (2) `memory_strategy = "compact_summary"` summarizes at ~80% of budget down to ~40%, also `/compact`, failure falls through; (3) whole turns dropped, never split mid tool pair; a too-big turn condenses to question + final answer. Disk `turns.jsonl` stays full. Plan P5.2: summaries in `compactions.jsonl`, latest line wins, chains the previous summary; “No `/compact` preview … yet.” Plan P5.3: results under 200 tokens left alone. Exit tests named in `docs/v2-status.md` P5 are met, including a live compaction recall on a real model.
- **Subagents, background processes, ask-user — wired; plan mode is not.** User guide Subagents and plan P6.3: `task` tool, fresh context, optional tool subset of the parent’s tools, shared approvals, max 4 concurrent (`[subagents] max_concurrent`), `max_depth` default 1 (no subagents of subagents), events indented `↳`, child sessions hidden from the picker, `meta.json` `parent`. Background and `ask_user` are in the user guide and marked done in plan P6.4 and P6.5 (TUI question dialog; `--print` answers “no user available”; JSON-RPC `question/answer`). Plan P6.6 checkbox is still `[ ]`: “Plan mode. A read-only mode … with `exit_plan_mode` … postponed by the maintainer” (status table). `docs/todo.md` still describes plan mode and `ask_user` as absent; that file is stale for `ask_user`.
- **Sessions, resume, CLI, TUI, headless, embedding.** User guide Sessions: new session per launch; `Ctrl+R` / `--resume`; `--name`; `Ctrl+N`; `Ctrl+L` clears view only; no in-app delete. `meta.json` fields include `workdir`, `branch`, `activity` (`idle`/`running`/`awaiting_approval`/`awaiting_answer`), `pid`, `cost_usd`, `parent` (user guide File formats; plan P6.1 progress log). CLI: `--print` with `--approve none|reads|all` and `--output text|json`, exit codes 0/1/2/3/130 (`src/print.rs`, user guide). `--headless` JSON-RPC 2.0 methods listed in plan P6.2: `initialize`, `session/new|resume|list|set_title|close`, `turn/send|cancel`, `approval/decide`, `shutdown`, plus `question/answer` from P6.5. One forwarder task per session so the turn response follows its events. `RuntimeCommand` is not the wire format. Library: `Harness::builder()` … `Session::send` / `Turn::next_event` / `finish` (README; `crates/arbe-runtime/examples/embed.rs`). Profile switch mid-session: `Ctrl+P` / `/profile` (user guide; plan log 2026-09-29, live grok-4.7 → llama3.2:3b → grok-4.7).
- **Observability, wired except export.** Plan P6.8 and user guide “Logs”: `~/.arbe/logs/arbeharness.<date>.log`, 14 days, `ARBE_LOG` default `info`, never the terminal. Spans `turn` → `tool`. Per-model-call line (first token, duration, tokens, stop), per tool, per turn, session summary on close. Cost only if the user sets `[[models]]` prices; no built-in prices; total in the TUI header and `meta.json` `cost_usd`; compaction calls count. The library does not install the log subscriber; the binary does (`CLAUDE.md` “v2 P6 additions”). `docs/v2-status.md` “Known limitations” still says “No cost display (the model catalog has no prices)” — that sentence is older than P6.8.

## What has a design doc but no implementation?

### Takeaway
Two designed capabilities have no code: plan mode (a checked task in the v2 plan, explicitly postponed) and desktop control (a 2026-09-29 proposal that says it is not in the v2 plan). Prompt caching, compaction, and the agent loop are implemented; only pieces of their design were dropped or left unmeasured.

### Cited Findings
- **Plan mode.** Plan P6.6 is the only unchecked P6 task: “A read-only mode (write/execute tools auto-denied) with `exit_plan_mode` requiring user approval of the plan — implemented as a profile/policy overlay, not a new `LoopPhase`.” Status table: “P6.6 plan mode postponed by the maintainer.” `docs/todo.md` still sketches a different design (`LoopPhase` plus `enter_plan_mode`/`exit_plan_mode`) and claims nothing like it exists. The user guide has no plan-mode section. A user can approximate read-only behavior with a custom profile (`tools = ["read_file", "list_dir", "glob", "grep"]` in user guide Profiles) but that is not enter/exit plan approval.
- **Desktop / computer use.** `docs/desktop-control-design.md` header: “**Status:** proposal, not implemented · **Written:** 2026-09-29 · **Scope:** after the v2.0 release bar (it isn't in `v2-implementation-plan.md` yet).” Plan status table only mentions it as “Desktop control designed … awaiting review.” The design specifies seven `desktop_*` tools, screenshot coordinates, `xcap`/`enigo` backends, Wayland unsupported, a new `arbe-desktop` crate, and per-app approvals. No `desktop_` tools appear in `TOOL_NAMES` or the user guide.
- **Designed then explicitly not built (still in the plan text).** P6.8: OpenTelemetry export “Deferred” (“a large dependency stack”). P4.6: session-scoped skills left out “rather than faked.” P5.2: no `/compact` preview, which the risk table had listed as mitigation. P2.6: no catalog `max_output_tokens`. P2.7: no provider token-count endpoint. P4.2: no profile-settings snapshot inside `SessionMeta`. P6.3: subagents do not get their own profile. P4.4: no HTTP MCP GET listener. Open question 1: Responses API “revisit after P2.4” — not revisited in later notes. Open question 3: OS-level `execute` sandbox out of scope. P3.5’s note that `RuntimeCommand::CancelTurn` had no dispatcher is partly overtaken by P6.2, which maps JSON-RPC methods onto the facade instead of using `RuntimeCommand` as the wire format (“Not built”).
- **Storage designed, not written by the runtime.** User guide file tree marks `events.jsonl` “reserved” and `mcp/` “unused; MCP servers are configured in config.toml.” `SessionStore::append_event` exists (`crates/arbe-storage/src/session_store.rs`) and the only repo match for `append_event(` is that definition — no runtime caller. Plan P7.5: “`list_events` has no caller.”

### Inferences
- “Design doc but no implementation” should be reserved for plan mode and desktop control. Everything else in the v2 plan’s task list is implemented with named deviations, except the release tag (P7.8) and the unfinished live vendor runs (P7.2).
- `docs/todo.md` must not be cited as the current gap list: nested instructions, todos, `ask_user`, background execution, and subagents are all implemented later, and its “gate not structurally enforced” and “no wiremock” items were closed by P7.4 and P7.1.

### Gaps
- The plan says desktop control is “awaiting review” but does not record a maintainer decision after 2026-09-29. Whether review happened is not in the repo.
- No second design doc was found for OpenTelemetry, session skills, or Responses API beyond the short deferral notes above.

## What limitations do the v2 plan or code comments still call out?

### Takeaway
Release blockers that the plan and `v2-status.md` still call open are live OpenAI and Anthropic runs, a human TUI session, and the `v0.2.0` tag plus binaries. Separately, the implementation notes list permanent product limits: no execute sandbox, weak 3B models, subagents without MCP or their own profile, unmeasured prompt-cache hits, Anthropic-only cache breakpoints, and several transport and security caveats.

### Cited Findings
- **Exit criteria still open** (`docs/v2-status.md` Summary and P2/P3/P7; plan status table):
  - P2 / P7.2: no live run against api.openai.com or Anthropic. `.github/workflows/live.yml` exists and “never run” / “not yet run (needs secrets)” (status file and plan P7.7). xAI exercises the OpenAI adapter, not `api.openai.com`.

  - Plan “Current focus” line still says “push + CI” is a blocker, but P7.7 *Done* says CI is green on Linux, macOS, and Windows after commit `2823e18` (a real bug: `trusted_projects` entries containing `..` never matched on Unix). The focus line is staler than the P7.7 note. `v2-status.md` cites GitHub Actions run 36579578868.

  - P0 status-table note “P0.3 not verified against a live Ollama server” is stale; P0 in `v2-status.md` and the 2026-09-28 log say Ollama tool use was verified live.

  - P3.10 “Not done: cost in the header” is stale relative to P6.8.
