# Sandbox the shell ArBeHarness leaves open

ArBeHarness already implements the 2026 coding-agent loop that peer CLIs and agent SDKs treat as the product: streaming tool rounds, approvals, file and shell tools, web tools, MCP, hooks, skills, compaction, nested instruction files, subagents, `ask_user`, background processes, headless JSON-RPC, and file-log observability short of OpenTelemetry. What it still lacks, against Claude Code, Cursor, Gemini CLI, and Codex as documented on 2026-09-29, is an OS-enforced sandbox around `execute`. That is the one absence that meets a three-product bar and changes what the harness can safely auto-approve. The next real gap is plan-before-edit as a permission posture, which this repo designed and then postponed. Desktop control, a classifier that auto-approves, MCP OAuth, plugin marketplaces, and OpenTelemetry are either local proposals or single-vendor patterns, not table stakes to chase. Live OpenAI and Anthropic runs, a human TUI pass, and a `v0.2.0` binary are release checks, not missing features. Internal docs disagree on dates: the acceptance checklist froze on 2026-09-29 still saying later P6 work had not started, while the implementation log through 2026-09-30 and the user guide describe that work as shipped.

## The coding loop is already in the binary

The local inventory, taken from the v2 plan, the user guide, and crate layout rather than from `docs/v2-status.md` or the stale `docs/todo.md` punch list, describes a user-facing harness. Four providers are wired by config (`ollama`, `openai` Chat Completions, `anthropic`, `openai_compatible`). Every model round streams. Retries happen only before the first event. Read-only tools run together; `write_file`, `edit_file`, `execute`, and `todo_write` do not. Deny rules apply in every approval mode. High-risk shell calls auto-approve only through a patterned rule. File tools refuse paths outside the workdir. A redactor scrubs known secrets from tool output before the model, the transcript, and the TUI. Untrusted project config cannot supply a provider endpoint, an approval policy, MCP, hooks, or web search. Sessions resume from an in-flight log. Compaction summarizes around 80 percent of the budget down toward about 40 percent, and `/compact` exists. Subagents run through a `task` tool with a fresh context, a depth cap of 1, and at most four at once. `ask_user`, background processes, and web fetch are in the guide. MCP is stdio plus streamable HTTP, with tools namespaced and `tools/list_changed` applied on the next message. Skills load from global and project folders, on demand by default. Headless mode is JSON-RPC 2.0. The library facade is `Harness` / `Session` / `Turn`. Logs are daily files with `turn` and `tool` spans, and cost appears when the user supplies prices. A 12-test live agent run passed on xAI `grok-4.7`, including files, shell, denials, resume, memory, skills, nested `AGENTS.md`, compaction, cancellation, MCP, and a hook veto. None of that belongs on a gap list.

The same inventory is explicit about limits of features that do exist, so they are not "missing." Subagents use the parent's configuration, do not connect MCP, and do not roll token counts into the parent. Nested `AGENTS.md` / `agent.md` / `CLAUDE.md` is appended once, in session memory, the first time a path tool touches that folder, and a resumed session shows it again; root instructions are not walked up parent directories and are capped at 8,000 characters. Prompt-cache breakpoints exist only on the Anthropic adapter and were not checked against a provider's cache counters. MCP images become text placeholders. There is no per-turn dollar ceiling, no `/compact` preview, no session-scoped skills, and the runtime never writes `events.jsonl` even though storage can append events. Output length is fixed at 4,096 tokens. Those are constraints on a shipped loop. `docs/todo.md` still calls `ask_user`, background execution, subagents, and nested instructions absent; that file is stale and loses to the plan log and the user guide. `docs/v2-status.md` still says P6.4 through P6.8 were not started; the 2026-09-30 log and the guide contradict it, and this report follows the log and the guide.

Against the SDK notes, this already covers most of what those docs call a production minimum when they bother to say "production" at all: a loop with an explicit stop (default 50 tool rounds, optional turn-token cap, stop on the third identical tool round), a fail-closed approval gate, a transcript that survives process restart, compaction, and MCP behind a trust boundary. Claude's own loop adds a dollar budget as "a good default" because unbounded runs continue until the model stops ([Agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)). OpenAI's production rules for human-in-the-loop are about not trusting a client-supplied snapshot ([Human-in-the-loop](https://openai.github.io/openai-agents-python/human_in_the_loop/)). ArBeHarness pauses approvals inside a live process and over JSON-RPC; it does not ship a serializable run-state that can be approved after the process dies. That is an embedder's gap, not a coding-CLI gap. Handoffs that replace the active agent are an OpenAI-specific primitive ([Handoffs](https://openai.github.io/openai-agents-python/handoffs/)) and are not a missing coding tool.

## Peers cage the shell; this harness only asks

The pattern with opened evidence from at least three serious coding products is an OS sandbox around the shell, plus a separate allow/ask/deny layer. Claude Code sandboxes Bash, PowerShell, and Monitor children with Seatbelt on macOS and bubblewrap plus socat on Linux and WSL2. Native Windows is unsupported. If the helper is missing, the default is a warning and an unsandboxed command unless `sandbox.failIfUnavailable` is set ([Claude Code sandboxing](https://code.claude.com/docs/en/sandboxing.md)). Cursor sandboxes with Seatbelt on macOS, Landlock plus seccomp on Linux, and that Linux sandbox inside WSL2 on Windows. The company reports sandboxed agents stop 40 percent less often, and that about a third of requests on supported platforms run sandboxed ([Cursor sandbox engineering post](https://cursor.com/blog/agent-sandboxing)). Gemini CLI selects Seatbelt profiles, Docker or Podman, a Windows integrity-level sandbox via `icacls`, optional gVisor, or experimental LXC ([Gemini CLI sandbox.md](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/sandbox.md)). Codex separates sandbox mode from approval policy: `read-only`, `workspace-write`, and `danger-full-access`, enforced with Seatbelt, a native Windows sandbox, or bubblewrap ([Sandbox](https://learn.chatgpt.com/codex/sandboxing.md)). Its engineering post says the sandbox instructions apply only to the Codex-provided shell tool, and that MCP tools are outside that sandbox and must guard themselves ([Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)). BleepingComputer's 20 July 2026 report treats sandboxes as already shipping in Cursor, Codex, Gemini CLI, and Google Antigravity, with the shared line that the agent is trusted inside the workspace and the host outside is protected ([BleepingComputer](https://www.bleepingcomputer.com/news/security/cursor-codex-gemini-cli-antigravity-hit-by-sandbox-escapes/)).

ArBeHarness has the approval half of that pair and a lexical path guard for file tools. The v2 plan's open question 3 puts containers, Seatbelt, landlock, and Windows job objects out of scope, and the user guide states that `execute` is not sandboxed. The default approval mode is still to prompt. That matters because the shell is the tool that reaches the host, package managers, and git. File-tool confinement does not bind `sh -c` or `cmd /C`. Cursor's own post describes the usability failure that follows: as approvals pile up, people stop reading them, especially with several agents in parallel, and models retry the same command until the tool result names the sandbox constraint ([Cursor sandbox engineering post](https://cursor.com/blog/agent-sandboxing)). A harness that can only prompt or trust a command-name prefix cannot make the low-friction mode those products now call the default.

The same sources say a sandbox is not the finish line. Pillar Security, as reported by BleepingComputer, reproduced escapes in Cursor, Codex, Gemini CLI, and Antigravity without breaking the syscall boundary: the agent writes a workspace file that an unsandboxed host tool later runs. Named cases include Cursor's `.claude` hook config (CVE-2026-48124, fixed in Cursor 3.0.0), a virtualenv interpreter the editor later launched, Git metadata that does not live in a directory named `.git`, a Codex allowlist that trusted `git show` by name (patched in v0.95.0), and a Docker socket shared by Codex, Cursor, and Gemini CLI. Google downgraded two Antigravity findings as hard to exploit because they need a trusted repo plus prompt injection. The Cymulate writeup this article attributes, and the GitHub advisories, were not opened, so those details stand only as BleepingComputer stated them, with no CVSS scores in the opened piece ([BleepingComputer](https://www.bleepingcomputer.com/news/security/cursor-codex-gemini-cli-antigravity-hit-by-sandbox-escapes/)). Claude documents its own unsandboxed retry (`dangerouslyDisableSandbox`) and warns that turning off the filesystem sandbox lets a command rewrite shell startup files or `~/.claude/settings.json`. Dangerous switches in project settings are ignored: `filesystem.disabled`, credential masks, and `bypassPermissions` from a repo settings file do not take effect ([Claude Code sandboxing](https://code.claude.com/docs/en/sandboxing.md); [Permission modes](https://code.claude.com/docs/en/permission-modes.md)). Gemini's own page says sandboxing reduces risk and does not eliminate it, that Windows Low integrity persists on files the sandbox wrote, and that Docker-in-Docker means mounting the Docker socket ([Gemini CLI sandbox.md](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/sandbox.md)). ArBeHarness already refuses to let an untrusted repo weaken approvals, MCP, hooks, or the provider. That is the right companion control. It does not substitute for an OS boundary on `execute`.

There is no shared mechanism to copy. Seatbelt appears in Claude Code, Cursor, and Gemini CLI. Bubblewrap is Claude's and Codex's Linux tool. Landlock plus seccomp is Cursor's. Docker, Podman, and gVisor are Gemini's. Native Windows containment is the industry hole: Claude Code does not support it, Cursor runs the Linux sandbox in WSL2 and calls a native Windows sandbox significantly harder ([Cursor sandbox engineering post](https://cursor.com/blog/agent-sandboxing)), and Gemini's `icacls` Low integrity level is mandatory-integrity, not a syscall sandbox, and it sticks after the session ([Gemini CLI sandbox.md](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/sandbox.md)). A Rust harness that claims Windows parity without WSL is either ahead of Claude and Cursor or is shipping something weaker than their Unix sandboxes. Ubuntu 24.04 AppArmor blocking unprivileged user namespaces is a documented bubblewrap setup failure, not a side note ([Claude Code sandboxing](https://code.claude.com/docs/en/sandboxing.md)).

Secret handling in the opened Claude sandbox doc is scoped to the sandboxed process (`deny` or `mask` for Bash only), and the page says there is no built-in credential deny list ([Claude Code sandboxing](https://code.claude.com/docs/en/sandboxing.md)). The patterns pass did not find general output redaction in the pages it opened. ArBeHarness already redacts known secrets from tool output. That is a strength relative to those pages, not a gap.

Two smaller context gaps sit near the table-stakes line and should not be confused with "no instructions." Claude concatenates ancestor `CLAUDE.md` files from the root down, loads subdirectory rules when those paths are read, and treats `AGENTS.md` as a portability file from v2.1.277, with `CLAUDE.md` winning if one is present ([Memory](https://code.claude.com/docs/en/memory)). Codex walks `AGENTS.md` from the git root to the working directory, capped at 32 KiB by default, and puts more specific instructions later in the prompt ([Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)). Gemini uses `GEMINI.md` as workspace background and loads skill bodies only on activate ([Agent Skills](https://geminicli.com/docs/cli/skills)). ArBeHarness re-reads the workdir root every turn, which is the right response to compaction dropping early prompt text, but it does not walk ancestors, and its nested-file injection is not durable. Claude's compactor re-reads `CLAUDE.md` for that reason ([Agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)). Path-scoped rule files were fully documented only for Claude in these notes, so they are not a three-product requirement. Codex's tool-list stability warning is relevant to a feature ArBeHarness already has: honoring `notifications/tools/list_changed` mid-conversation changes the tools array and blows the cached prefix ([Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)). ArBeHarness applies that notification at the next message and sorts tools by name. The cache-miss cost is real for Anthropic breakpoints; it was never measured here.

## Plan mode is the permission this repo postponed

Plan-before-edit is the other capability several coding CLIs ship and this repo deliberately does not. Claude Code's `plan` mode blocks source edits until the user approves a plan. Claude may still read and, depending on the classifier, run shell commands. Entry is Shift+Tab, `/plan`, or a permission-mode flag ([Permission modes](https://code.claude.com/docs/en/permission-modes.md)). Cursor's Plan mode can hand execution to a cloud agent, and Ask mode keeps a read-only sandbox even if "Run everything" is on ([Cursor changelog 2.5](https://cursor.com/changelog/2-5)). Cline's plan mode cannot modify files or run commands; history carries into act mode ([Plan and Act](https://docs.cline.bot/core-workflows/plan-and-act)). Gemini CLI exposes `enter_plan_mode` and `exit_plan_mode` as tools ([Tools reference](https://geminicli.com/docs/reference/tools/)). OpenCode's Plan agent defaults edits and bash to `ask`, which a config can change, so it is not a hard deny ([OpenCode agents](https://opencode.ai/docs/agents/)). Codex ships `update_plan` in the same tools array as the shell. The post does not describe it as a mode that blocks edits ([Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)).

The notes do not fully agree on whether this is table stakes. The coding-CLI inventory, which opened those product pages, treats plan mode as a common primitive alongside todos, ask-user, and subagents. The patterns pass opened Claude and Cursor only, refused to use unopened OpenCode or goose pages, and concluded that a planning *affordance* is widespread while a read-only *permission mode* is not yet a three-product bar. The honest merge is: hard or near-hard edit blocking is documented for Claude Code, Cursor, and Cline; Gemini and OpenCode ship a weaker in-loop version; Codex's plan tool is not that control. ArBeHarness's only unchecked P6 task is this feature, postponed by the maintainer, specified as a profile and policy overlay that auto-denies write and execute until `exit_plan_mode`, not as a new loop phase. The user guide has no plan-mode section. A custom profile limited to read and search tools can imitate the posture and cannot do enter, exit, and approval of a plan. `docs/todo.md` sketches a different design and claims nothing like it exists; the plan task is the one to trust. Local design is stricter than Claude's plan mode, which still allows reads and sometimes shell. That is a small policy overlay on a gate the harness already has. It is higher leverage than a new tool, and lower leverage than sandboxing `execute`, because a read-only profile already approximates it and peers do not implement it the same way.

Todos, ask-user, and subagents fall out of the gap list on purpose. Claude, Gemini CLI, OpenCode, Cursor, Cline, Factory, and Amp all expose some form of them, and so does ArBeHarness. The split those products still argue about is whether the primitive is a named tool with permission rules or a behavior without a stable id. Factory's `Task` tool and OpenCode's child sessions are the same idea as ArBeHarness's `task` tool. What this repo does not do, and Claude's Agent SDK does, is give a subagent its own MCP servers, tool allow-list, and permission mode ([Subagents](https://code.claude.com/docs/en/agent-sdk/subagents)). That is one vendor's SDK surface plus this repo's own "not done" notes, not a three-CLI hole.

## Designed extras and rare patterns are not the chase

Two items have a local design and no code. Plan mode is the postponed v2 task above. Desktop control is a 2026-09-29 proposal, explicitly not in the v2 plan, awaiting review, with no later maintainer decision recorded in the repo. It specifies seven `desktop_*` tools, screenshot coordinates, `xcap` and `enigo`, Wayland unsupported, and a new crate. No such tools are registered or documented for users. Peer evidence does not make computer use a table stake. Cursor cloud agents can drive a desktop and a browser ([Cloud Agents](https://cursor.com/docs/cloud-agent)). The OpenAI Agents SDK's `ComputerTool` is a local interface the application implements, and hosted shell is a container the service runs; the model only proposes actions ([Tools](https://openai.github.io/openai-agents-python/tools/); [Equipping Responses API with a computer environment](https://openai.com/index/equip-responses-api-computer-environment/)). Codex's docs navigation lists computer use, but that article body was not retrieved, so behavior is not restated here. Computer use was not in the Claude Code or Gemini CLI tool tables that were actually read. The patterns pass did not confirm computer use, a browser tool, OpenTelemetry, or a JSON-RPC embedding API from an opened page; ArBeHarness already has the JSON-RPC API, which that pass simply did not see. Building desktop control now would copy a Cursor cloud feature and an OpenAI hosted tool, not close a gap every coding CLI has.

The user guide's "not yet active" table is narrow and should stay that way: session-only skills, and `events.jsonl`. Both are storage or config ideas with no user-facing connection. Session-scoped skills were left out on purpose rather than faked. OpenTelemetry export was deferred as a large dependency. The patterns pass found no opened product doc that makes OpenTelemetry a three-CLI requirement. OpenAI's Agents SDK traces to its own dashboard by default ([Tracing](https://openai.github.io/openai-agents-python/tracing/)). Other stacks point at LangSmith, OpenTelemetry, or the application. ArBeHarness already logs spans and token counts to a file and prices a call only when the user fills in prices. Export format is not why a turn is unsafe.

Other local deferrals are real and small. The OpenAI Responses API was considered and not adopted; Chat Completions is the OpenAI path, and the "revisit" was not done. That protocol is where OpenAI's hosted shell, container id, and `/responses/compact` live ([Shell](https://developers.openai.com/api/docs/guides/tools-shell); [Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/)). It matters if the goal is OpenAI-hosted computers. It does not matter for the local loop that already streams through an OpenAI-compatible server. There is no HTTP MCP GET listener for server-initiated messages, no catalog `max_output_tokens`, no provider token-count endpoint, no profile snapshot inside session metadata, and no subagent-specific profile. Compaction has no preview step. None of these are what Claude, Cursor, Gemini CLI, and Codex collectively treat as the harness.

The patterns that are explicitly experimental, optional, or single-vendor should not be promoted into a roadmap by omission. Gemini marks LXC sandboxing experimental ([Gemini CLI sandbox.md](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/sandbox.md)). Claude marks agent-typed hooks experimental; command, HTTP, and prompt hooks are not ([Hooks guide](https://code.claude.com/docs/en/hooks-guide.md)). MCP authorization in the 2025-11-25 spec is optional, and stdio implementations are told not to follow the OAuth flow ([MCP authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)). Shipping stdio MCP without OAuth, which is what ArBeHarness documents, is still compatible with that spec. Streamable HTTP plus OAuth is the HTTP-transport story, and these notes did not show three coding agents implementing it. Later MCP spec pages on tasks and URL elicitation were not opened.

Classifier auto-approval is past experimental at Anthropic: as of v2.1.283, auto mode is the default for interactive terminal and VS Code sessions, a second model blocks some escalations, and the same page says it does not guarantee safety ([Permission modes](https://code.claude.com/docs/en/permission-modes.md)). The coding-CLI inventory also saw Codex's `approvals_reviewer = auto_review`, goose Smart Approval, and Amp's optional `amp.ai.ask` plugin, and inferred a 2026 pattern. The patterns pass opened only Claude's classifier in full and said not to treat auto-review as confirmed for three products. Goose's read/write split is "best effort" and interpreted by the provider ([goose permission modes](https://goose-docs.ai/docs/guides/managing-tools/goose-permissions)). Amp's default is the opposite: tools run with no approval unless a plugin adds policy ([Amp tools](https://ampcode.com/docs/tools)). A second-model reviewer is not the gap to close while `execute` is unsandboxed. Static deny rules, which ArBeHarness already applies in every mode, are the layer Claude says still wins over auto and over bypass.

Deferred tool schemas are a 2026 SDK answer to huge MCP surfaces, documented for Claude's tool search ([Agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)) and OpenAI's `defer_loading` ([Tools](https://openai.github.io/openai-agents-python/tools/)). They were not established here as three coding CLIs. Checkpoints that revert files without wiping the transcript are documented for Cursor ([Cursor Agent](https://cursor.com/docs/agent/overview)) and Cline's shadow git repo ([Checkpoints](https://docs.cline.bot/features/checkpoints)). Aider undoes a real git commit instead ([Git integration](https://aider.chat/docs/git.html)). The patterns pass opened no checkpoint page and would not call this a three-product bar. Worktrees are a first-class Claude tool ([Tools reference](https://code.claude.com/docs/en/tools-reference)); Codex's worktree article was not fetched; Cursor cloud agents use a separate branch. Plugin marketplaces package skills, hooks, MCP, and rules ([Cursor changelog 2.5](https://cursor.com/changelog/2-5); [Droid CLI overview](https://docs.factory.ai/cli/getting-started/overview); [Amp plugins](https://ampcode.com/docs/customize/plugins)). ArBeHarness already has those pieces separately. A bundle format is distribution, not a missing loop. Programmatic tool calling in a hosted V8 isolate, OpenAI handoffs, Amp's oracle and image tool, Claude's cron and LSP tools, and agent teams are one product's surface. A search excerpt claimed Claude agent teams sit behind an experimental flag; that page was not opened, and the official hooks guide treats team events as real, so the conflict stays unresolved. Factory's full autonomy-level page, Codex's tool catalog, goose's extension list, Cline's auto-approve settings, and Antigravity's delta versus Gemini CLI were not opened. Gemini's docs banner says unpaid and Google One users moved to Antigravity CLI on 18 June 2026, while the tools page itself is still dated 1 September 2026. Do not treat unopened bodies as absences in ArBeHarness.

## Open vendor runs are a release gate, not a missing feature

The v2 status file and the plan's status table still hold P2, P3, and P7 short of Done for reasons that do not add a tool. There has been no live run against `api.openai.com` or Anthropic. xAI exercises the OpenAI-compatible adapter, not OpenAI's own host. Anthropic is fixtures plus HTTP tests. Stream fixtures were written from documented formats, not captured traffic. A `live.yml` workflow exists and had not been run, because it needs secrets. The interactive TUI has unit tests and a captured layout, and nobody has typed into it since the v2 changes; the checklist names streaming, the approval dialog including a subagent, Esc, and resume. `v0.2.0` is untagged, crates are `publish = false`, the README says there are no prebuilt binaries, and the license is proprietary until one is chosen. Prompt-cache hits were not measured. Web search was not run against a real key. Windows symlink-escape tests are Unix-only because Windows CI cannot create unprivileged symlinks. The plan header's test count was not re-run against the status file's count in this research pass, so those two numbers are unreconciled. A stale "current focus" line still talks about CI as a blocker after a later note says CI is green. None of that is a product gap relative to Claude Code or the Agents SDK. It is the difference, which the plan itself draws, between tasks checked off and a phase whose exit criteria include a human and a live vendor.

## Conclusion

The highest-leverage missing piece is an OS sandbox for `execute` on macOS and Linux, kept as a separate layer from the approval policy that already exists, with project-written hooks and command-name allowlists treated as hostile the way the 2026 escape reports describe. On native Windows the peer docs do not offer a mechanism worth claiming as parity. The second piece is the postponed plan-mode overlay: auto-deny writes and shell until a person accepts the plan, without a new loop phase and without pretending a static read-only profile is the same thing. The third, and only if embedding is a goal equal to the CLI, is a durable pause token for an in-flight approval so a headless host can restart without inventing its own loop, which is the production shape OpenAI, LangGraph, and Pydantic document. Ancestor-walking `AGENTS.md`, persisted rather than shown once in memory, is the context portability fix after those, and it is smaller because root instructions already reload every turn.

Do not spend the next cycle on desktop control, OpenTelemetry, a plugin marketplace, a classifier auto-mode, Responses API hosted shells, MCP OAuth, or a wider hook catalog. Those are either local proposals, single-vendor products, or packaging around capabilities this harness already runs. The work that makes v2 honest in public is the sandbox, the plan overlay, and the vendor and TUI checks the status file already names.
