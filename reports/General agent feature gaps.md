# General agents outlive the coding session

A general-use agent in 2026 is an account-scoped worker that stays reachable after the laptop closes, starts from a clock or an incoming event, and acts on mail, calendar, a browser, and sometimes a desktop, stopping for sends, payments, and passwords. That shape is what OpenClaw’s self-hosted Gateway, Grok’s consumer app plus Grok Bot, Copilot Autopilot (the agent formerly called Scout, not Windows device enrollment), and the ChatGPT Work, Gemini, Claude, and Perplexity Computer pages all describe, with different owners for the machine that keeps running. ArBeHarness already implements the inner loop those products either embed or keep beside the life agent: a session the user starts, a workdir boundary for files, streaming tools, approvals, MCP, skills, subagents, `ask_user`, background processes, and headless JSON-RPC. It does not own presence, a trigger that opens a turn by itself, connectors into a person’s accounts, or an identity that survives a change of repository. If this harness hosted a general agent, the primitives to add are an always-on session owner, a scheduler, action-class approvals, person-scoped memory, and an execution place that is not the repo. OpenClaw already splits that owner from the coding loop and can run Codex, Claude Code, and GitHub Copilot as executors. Chat-app plugins, telephony, and a tenant directory are products above that split, not the split.

## One account stays up and reaches the apps a person already lives in

Presence is the first cut between a general agent and a coding CLI. OpenClaw’s own job statement is a Gateway between chat apps and an agent on the operator’s hardware, with no Foundation-hosted service in the middle, one process as the source of truth for sessions, and a background service after `openclaw gateway install` ([Docs home](https://docs.openclaw.ai/)). **Telegram and WebChat ship in core; most other messengers are official plugins**, including Discord, Slack, Signal, WhatsApp, iMessage, Teams, Matrix, and an SMS plugin, plus a separate Voice Call plugin named as telephony via Plivo, Telnyx, or Twilio ([Chat channels](https://docs.openclaw.ai/channels)). Companion nodes (macOS, iOS, Android, watchOS) expose camera, screen, location, and device commands, but channel messages still land on the Gateway, not on the phone ([Nodes](https://docs.openclaw.ai/nodes)). The pages opened do not confirm email as a channel. Gmail and IMAP showed up only in search snippets of automation pages that were not fetched, so mail is not treated as a confirmed OpenClaw ingress. Per-channel voice matrices and the telephony setup pages were also not opened. Voice on the pages that were opened is several surfaces at once: voice notes and text-to-speech, a Talk and voice-wake entry on the nodes index, a Discord catalog blurb, and that telephony plugin ([Features](https://docs.openclaw.ai/concepts/features)).

The consumer products reach the user through the vendor’s own web, phone, and desktop apps, not through an open messenger catalog. **ChatGPT Work syncs cloud chats across web, mobile, and desktop, and Codex is a separate view with a separate history** ([ChatGPT Work and Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)). A cloud-browser task keeps going after the computer closes ([Cloud browser](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt)). The same vendor’s older agent article disagrees with itself: its overview says agent mode “is no longer available” and points at Work and the cloud browser, while the rest of that article still describes agent mode as a current paid feature. Atlas still documents a different agent that acts in the browser the user already has open and cannot see the file system ([ChatGPT agent](https://help.openai.com/en/articles/11752874-chatgpt-agent); [Atlas](https://help.openai.com/en/articles/12628199-using-ask-chatgpt-sidebar-and-chatgpt-agent-on-atlas)). Those are not one product. Gemini Spark is the Gemini mobile app, the Mac app, and gemini.google.com, personal accounts only, and it is absent in the EEA, Nigeria, Switzerland, and the UK ([Gemini Spark](https://support.google.com/gemini/answer/17094507?hl=en)). Claude’s merged chat-and-Cowork experience is rolling out on web, desktop, and mobile; a task that needs local files or apps still needs Claude Desktop open, and a cloud task does not ([One Claude](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)). Perplexity Computer is a workspace mode beside Ask Anything, on web and the phone, with no local install for the cloud product ([What is Computer?](https://www.perplexity.ai/help-center/en/articles/13837784-what-is-computer)). None of the Gemini, Claude, or Perplexity pages opened here describe a voice session that steers the agent. ChatGPT Voice can start Work and can keep a task in text after the call ends, and **spoken approval is not supported on web or mobile** ([ChatGPT Work and Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)).

Grok’s docs split the same way, and they carry a source conflict that has to stay visible. grok.com and the Grok mobile apps are the chat assistant: Imagine, voice, file upload, connectors, skills, and scheduled automations ([Welcome to Grok](https://docs.x.ai/grok/overview); [Automations](https://x.ai/news/grok-automations)). Grok on X is search over public posts and the web, not a connector or computer-use agent ([About Grok](https://help.x.com/en/using-x/about-grok)). **Grok Bot is the multi-step agent: messaging, approvals, connectors, routines, and a persistent cloud computer with a browser, filesystem, and terminal, and the docs say work continues while the laptop is closed** ([Grok Bot overview](https://docs.x.ai/grok-bot/overview)). The same docs.x.ai pages say those computers run in Cursor’s cloud, that access can come from paid Cursor plans, that Grok Bot uses Cursor authentication, and that training opt-out and privacy settings are Cursor account settings ([Approvals, security, and privacy](https://docs.x.ai/grok-bot/approvals-security-and-privacy)). Event examples for routines are a Slack message or a GitHub notification “via Cursor account integrations,” described as separate from Slack and GitHub plugins ([Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)). Those sentences were not checked against cursor.com. This report does not treat “Grok runs inside Cursor” as an established fact. It treats the computer, the sharing rules, and the approval buttons as claims those pages make, with Cursor named on the pages themselves. help.x.com still attributes the model to xAI, while docs.x.ai is titled SpaceXAI (xAI).

Microsoft’s naming trap is the other way around. **Windows Autopilot is a device-enrollment stack for new PCs and HoloLens 2, Entra or hybrid join, and MDM, not an assistant** ([Overview of Windows Autopilot](https://learn.microsoft.com/en-us/autopilot/overview)). The agent is Copilot Autopilot, previously Scout. The 2 June 2026 announcement introduced Scout as an always-on personal agent with its own identity, connected to Teams, Outlook, OneDrive, SharePoint, chats, email, calendar, and contacts, and **said it was powered by OpenClaw**. The 25 September 2026 Copilot post says Autopilot was previously called Scout, describes a cloud-hosted teammate in the tenant that keeps working while the user sleeps, and **does not repeat OpenClaw or the desktop-app details** ([Introducing Microsoft Scout](https://www.microsoft.com/en-us/microsoft-365/blog/2026/06/02/introducing-microsoft-scout-your-always-on-personal-agent/); [New Copilot, 25 September 2026](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)). No page opened for this pass says whether the September product still embeds OpenClaw. Autopilot was still private preview at the end of September 2026, and the post is an announcement, not an admin spec of triggers or tools. Foundry’s separate “autopilot agents,” in public preview, are directory actors with a licensed mailbox, calendar, OneDrive, and Teams presence ([Foundry enterprise agent distribution](https://devblogs.microsoft.com/foundry/from-building-agents-to-working-with-them-enterprise-agent-distribution-in-microsoft-foundry/)).

## Identity, memory, and a clock replace the next prompt

Identity is whoever the side effects are allowed to impersonate. OpenClaw’s operational memory is files in the agent workspace, default `~/.openclaw/workspace`: optional `USER.md`, curated `MEMORY.md`, and daily notes, with the model told it only remembers what is saved to disk ([Memory overview](https://docs.openclaw.ai/concepts/memory)). The lore page calls `SOUL.md` and `AGENTS.md` sacred texts; the memory overview never mentions them, so those names are not the memory system on the pages that specify injection ([Lore](https://docs.openclaw.ai/start/lore)). A multi-user Gateway can update the requester’s own `USER.md`, and the project states the limit in plain language: **one gateway is one trust domain, not a hostile multi-tenant boundary** ([Why OpenClaw](https://docs.openclaw.ai/start/why-openclaw)). Dreaming promotes into `MEMORY.md` by default, untrusted and system-derived candidates are excluded from that path, direct writes are not, and promoted memories have no time-based retention bound. `openclaw memory forget` exists; original transcripts and external copies remain.

Grok Bot’s overview says each Bot keeps “stable preferences, role context, and summaries of prior work,” that bots do not share that learned context, and that a shared computer is not a security boundary between one user’s bots ([Grok Bot overview](https://docs.x.ai/grok-bot/overview); [Computer and apps](https://docs.x.ai/grok-bot/computer-and-apps)). No opened grok.com page documents a memory screen where the user edits or deletes individual memories. Skills are the documented cross-chat store there, and a FAQ aside says the wrong host can hide Projects without saying what a Project contains ([Grok FAQ](https://docs.x.ai/grok/faq); [Grok skills](https://x.ai/news/grok-skills)). Grok on X personalizes from X profile and post data under a separate opt-out. That is not a memory file.

Microsoft runs three identity stories at once, and they should not be merged. Microsoft 365 Copilot and Researcher act as the signed-in user and cannot exceed that user’s Graph permissions ([Copilot extensibility](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/data-privacy-security)). Copilot Studio unattended triggers use the maker’s connection credentials, and publishing warns that people who talk to the agent may act with the author’s access ([Event triggers](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-triggers-about)). Scout’s June post said every agent has its own Entra identity, not a shared service account. The September Autopilot post says the agent has its own identity and can be @mentioned with permissions and audit behind it, and it does not say whether that identity has a mailbox or is an Entra Agent ID, a licensed user, or both. Foundry autopilot agents have both an agent identity and a productivity-licensed user account. Copilot Studio’s per-user file memory is a different feature again: preview, GitHub Copilot harness only, deleted after 28 days without use, and off in Teams channels ([Memory preview](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/memory-overview)). Researcher memory was still “to be released soon” on the FAQ that was opened ([Researcher FAQ](https://learn.microsoft.com/en-us/microsoft-365/copilot/faq-researcher)).

Claude’s merged product uses chat memory inside tasks, lets the user view, edit, and delete it, and refuses to save government IDs, criminal history, financial account numbers, and immigration status ([One Claude](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)). ChatGPT Work’s share of a scheduled task copies instructions onto the recipient’s own schedule and does not transfer memories, credentials, or history ([ChatGPT Work and Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)). Gemini Spark can draw on past chats, saved instructions, and connected Google apps through Personal Intelligence, and Keep Activity must be on ([Gemini Spark](https://support.google.com/gemini/answer/17094507?hl=en)). Perplexity’s one opened page says persistent memory stores preferences inside the cloud sandbox; the dedicated memory article was not opened.

Proactive runs are the other half of “always on.” Across ChatGPT Work, Gemini’s two schedulers, Claude scheduled tasks, and Perplexity’s condition monitors, a person can pause a job and the cloud product does not need the laptop open ([Schedule actions](https://support.google.com/gemini/answer/16316416?hl=en); [Claude scheduled tasks](https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork)). **Claude says each scheduled run is its own session and cannot attach a folder on the computer.** ChatGPT Work also documents webhook tasks on new Gmail, Slack channel messages, and GitHub pull requests, with an admin switch required for Enterprise, Edu, and Healthcare, and Healthcare event tasks are not under a BAA ([ChatGPT Work and Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)). Whether those events resume an existing chat or start a new one is not stated. OpenClaw exposes `cron` and `heartbeat_respond` and lists cron, hooks, and webhooks as an automation area; the schedule-kind and Gmail pages were not opened, so interval and mailbox behavior are not claimed here ([Tools](https://docs.openclaw.ai/tools); [Docs home](https://docs.openclaw.ai/)). grok.com automations are once through yearly, or an email-header match that is SuperGrok-only, and each run is a saved conversation ([Automations](https://x.ai/news/grok-automations)). Grok Bot routines are owned by one Bot, capped at 50, and the docs say a long absence can pause them if the user does not answer ([Skills and routines](https://docs.x.ai/grok-bot/skills-routines-and-automations)). Copilot Studio can fire on a recurrence as short as the maker dares, or on SharePoint, OneDrive, Planner, Dataverse, and new mail, then choose only among actions the maker already defined. A 10-minute recurrence bills a message every 10 minutes ([Event triggers](https://learn.microsoft.com/en-us/microsoft-copilot-studio/authoring-triggers-about)). Researcher does not do this: the user opens it and asks. September’s Autopilot is described as watching channels and picking work up days later without a prompt; its trigger catalog was not in any Learn article opened here.

## Mail and the desktop stop at send, pay, and sign-in

Life tools are connectors first and a computer second. grok.com documents OAuth connectors for Gmail, Google Calendar, Drive, Outlook mail and calendar, Teams, SharePoint, OneDrive, Salesforce, GitHub, Notion, Linear, and others, plus a public MCP URL ([Connectors](https://docs.x.ai/grok/connectors)). **Private and localhost MCP URLs are rejected.** Gmail starts read-only; send and modify are separate scopes, and the opened page does not describe a “send this?” dialog once send is granted. The May 2026 connector post says Outlook can draft and send and that Google Workspace can be read and write ([Connectors launch](https://x.ai/news/grok-connectors)). Gemini Spark’s connected Workspace list is the same life surface, spelled out: calendar create and cancel, Gmail draft and reply, Drive create and delete, Tasks, Photos, Search, flights, and hotels ([Gemini Spark](https://support.google.com/gemini/answer/17094507?hl=en)). ChatGPT Work’s examples include package tracking from connected mail, a DMV booking prepared for approval, and invoice reconciliation ([Cloud browser](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt)). Perplexity names Gmail, Outlook, GitHub, Slack, Notion, and Salesforce and shows a prompt that researches, builds a deck, and sends it through Gmail; that page does not say the send waits for a second confirmation ([What is Computer?](https://www.perplexity.ai/help-center/en/articles/13837784-what-is-computer)). OpenClaw’s built-in tool table does not list mail, calendar, or payments. Those would arrive as skills, plugins, or MCP, and the tools overview says its table is representative, not the full policy reference, which was not opened. A ClawHub search box that accepts the word “calendar” is not a bundled calendar tool.

The browser is the fallback when no connector exists, and the safer default in the consumer docs is a remote session that starts logged out. ChatGPT’s cloud browser has its own cookies, asks before a new site unless the user weakens that, and **still asks before a booking, a payment, or another hard-to-reverse commitment**. The password goes through a form the model does not see ([Cloud browser](https://help.openai.com/en/articles/20001280-using-cloud-browser-in-chatgpt)). Atlas logged-in mode and Gemini’s local Chrome are the dangerous twin: they act as the user on sites already signed in. Gemini’s remote browser does not start signed in, and sign-in stops the task until the user takes over. Claude’s documented browsers are the desktop app’s browser or the user’s Chrome, and both need the desktop app open, so Claude is the exception to “cloud browser is table stakes” ([One Claude](https://support.claude.com/en/articles/16761823-claude-cowork-and-chat-are-one-claude)).

Desktop control is real and not the default personal shape. Claude computer use, beta, Pro and Max, macOS and Windows, **says there is no sandbox between Claude and the apps on screen**. Permission is per app, every session; investment, trading, and cryptocurrency apps are blocked; a link in an allowed app can still open a browser the user did not allow ([Computer use](https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork)). OpenClaw’s `computer` tool drives the Gateway desktop or a paired node. An explicit coding profile excludes it unless it is added back. Windows and Linux `cua-computer` is experimental and limited to the primary display. High-risk families are classified, and **classification does not add a per-action prompt**. Sandboxing and exec approvals are off by default because “default OpenClaw is a trusted single-operator assistant” ([Computer use](https://docs.openclaw.ai/nodes/computer-use); [Security](https://docs.openclaw.ai/gateway/security)). That is the opposite of a default-deny coding sandbox, and it is why an OS shell sandbox is not the headline gap once the view leaves coding CLIs. The general-agent boundary on these pages is which computer, whose cookies, and which action class stops for a person. Cloud workers and Host Desktop are OpenClaw Labs flags, not the default install ([Experimental features](https://docs.openclaw.ai/concepts/experimental-features)).

Grok Bot’s computer page claims one shared cloud computer for all of a user’s bots: shared files, shared browser logins, shared command-line credentials, a per-bot screen, one computer-use task at a time, and a `/workspace` path. The computer is not the user’s Mac or Windows machine. Local execution is a separate switch that **defaults to ask every time**, and that switch does not block the cloud computer ([Computer and apps](https://docs.x.ai/grok-bot/computer-and-apps); [Approvals](https://docs.x.ai/grok-bot/approvals-security-and-privacy)). The Cursor attribution above sits on this claim. Approvals on those pages are Allow once, Always allow, and Deny. Auto Review can ask first or allow automatically; if both match, ask first wins. Team rules are a ceiling. Passwords, 2FA, CAPTCHA, and payments are supposed to be a human takeover, not text in the chat. The opened pages do not include the security FAQ’s full action list.

Microsoft splits the desktop three ways. Copilot Studio computer use drives a hosted browser, a Cloud PC pool, or a registered Windows machine, with maker credentials as the autonomous default, and the FAQ says human-supervision mail is probabilistic and should not be relied on as a safety fail-safe ([Computer use](https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use); [FAQ](https://learn.microsoft.com/en-us/microsoft-copilot-studio/faqs-computer-use)). Windows Copilot Actions, an Insider experiment as of the November 2025 post, runs in a separate agent workspace under a separate local account, off until the user enables it, with known folders only unless the user grants more ([Securing AI agents on Windows](https://blogs.windows.com/windowsexperience/2025/10/16/securing-ai-agents-on-windows/)). September Autopilot’s “own computer” is stated as cloud-hosted in the tenant. No opened page maps that computer’s reach. What stays local, when a product says so, is OpenClaw’s Gateway, transcripts, memory files, and credentials, with model calls leaving the machine unless the operator picks Ollama, vLLM, or another self-hosted endpoint; Perplexity’s optional Portable Computer on supported NVIDIA hardware; Claude’s and Gemini’s local slice only while the desktop app is awake; and ArBeHarness’s process, workdir, and `~/.arbe` store. Grok Bot, ChatGPT’s cloud browser, Autopilot as announced in September, and default Perplexity Computer keep the running machine in someone else’s cloud.

## The coding loop overlaps; the life around it does not

ArBeHarness, as inventoried from this repo’s user guide and v2 plan through 2026-09-30, is a repo-scoped coding harness. The user starts a session. File tools refuse paths outside the workdir. The model gets a streaming tool loop, an approval gate, MCP as a client, instruction files and skills, subagents through `task`, `ask_user`, background shell processes, web fetch and optional web search, a one-line `remember` into global or project `memory.md`, and a headless JSON-RPC control plane. `execute` is not OS-sandboxed. Desktop control exists as a design note with no tools registered. Plan mode was postponed. There is no scheduler, no inbound chat channel, and no connector to mail or calendar.

**Already the same shape.** The inner turn is what OpenClaw keeps when it plugs in a vendor harness, and what ChatGPT keeps beside Codex rather than inside it. Approvals that can ask, allow, or deny, a structured question back to the user, skills as instruction files rather than hidden tools, MCP, subagents, a shell with a process table, and web fetch are all present on both sides. OpenClaw’s `ask_user` and ArBeHarness’s `ask_user` are the same pause. OpenClaw’s file and exec tools, and its coding profile, are the same job as this harness’s workdir tools. Headless JSON-RPC is a control plane for a session a host already opened. It is not, by itself, a Gateway that accepts a Telegram message at 3 a.m.

**Absent because the product is a coding session, and should stay absent as product surface.** The channel catalog, SMS, the Voice Call plugin, phone nodes, Imagine watermarks, Companions, Office role-skills inside Excel and Word, an IT plugin registry, and a licensed agent mailbox with an org-chart slot are how OpenClaw, Grok, and Microsoft sell or distribute a general agent. OpenClaw’s own architecture page says native plugins are the extension mechanism and that the project is not a multi-tenant security boundary. Building Telegram, telephony, or an Entra-style identity system in this repo would copy the product that sits on the harness. Scout’s June desktop-plus-MCP reach and Foundry’s mailbox are Microsoft’s tenant product. The September post’s silence on OpenClaw is a reason not to treat “embed OpenClaw” as a current Microsoft requirement, and equally a reason not to treat Autopilot as a spec this repo can implement from the announcement.

**Absent, and required if this harness became the host of a general agent.** Five primitives are the harness, because the products above all need them and none of them is a messenger:

## Conclusion

The general agent does not retire the coding loop. The products that stay coherent keep the loop swappable or give it a separate history: OpenClaw can host Codex, Claude Code, and Copilot while the Gateway still owns sessions, and ChatGPT refuses to mix Codex history into Work. A harness that grows Telegram plugins, a phone bridge, or a tenant directory will have built someone else’s product around an unchanged session model. The session model is the part that has to change: a process that is already running, a stored instruction that fires without a typed prompt, a person rather than a workdir as the memory key, and a stop rule whose nouns are “send” and “pay” rather than `cargo test`.

Microsoft’s rename is the caution against copying a teammate from a blog post. June 2026 said Scout was powered by OpenClaw and could reach a desktop, a browser, and MCP servers. September 2026 renamed it Autopilot, stressed a cloud tenant, and did not repeat that stack. Windows Autopilot remains a PC-provisioning product and is the wrong target entirely. Grok Bot is the other caution: its computer and its account settings are described on docs.x.ai in Cursor’s vocabulary, unchecked against Cursor, so a harness should copy the approval and routine ideas only as those pages state them, not as proof of whose cloud the bytes sit in. The coding-CLI finding that an OS sandbox around `execute` is the peer gap does not become the general-agent milestone. OpenClaw documents the unsandboxed single-operator default on purpose, and Claude documents computer use with no sandbox at all. Isolation, on this evidence, is which machine runs and which credential the model is allowed to see.
